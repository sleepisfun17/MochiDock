- `social-preview.png`: the 1280 x 640 card GitHub shows when the repository link is shared. Regenerate with `pwsh -NoProfile -STA -File tools/make-social-preview.ps1` after a Release build, then upload it by hand in the repository's Settings > General > Social preview (GitHub has no API for it).
- `live/<card>-<theme>.png` (and `live/<card>-<theme>-<mascot>.png`): captures of the running dock in any theme (Default, Hojicha, Kuro Night, Matcha) and, optionally, with a chosen mascot. See below.

## How the live captures are made

From an **elevated** PowerShell on the local console (not RDP, which gives wrong CPU/GPU readings), with MochiDock already running and "Exclude from screen capture" off in Settings:

1. `pwsh -NoProfile -STA -File tools/capture/backdrop.ps1` in a separate window: a borderless gradient window behind the dock so no other program shows. It closes itself after 30 minutes or on Esc.
2. `tools/capture/capture-stills.ps1 -Theme default|hojicha|kuro-night|matcha [-Mascot auto|mochi|matcha-mochi|hojicha-mochi|kuro|shiro] [-Apply]`: clicks each tab and saves a cropped PNG per card. Without `-Apply` the dock must already wear that theme; with `-Apply` (or a `-Mascot`) the script switches the theme and mascot in quick settings itself and puts the previous ones back at the end. For example `-Theme kuro-night -Mascot kuro -Apply` saves `live/<card>-kuro-night-kuro.png`. It uses UI Automation to find the tabs, and it blanks text matching the patterns in the script (account line, calendar title). It skips Settings and Clipboard because they show personal data.
3. `tools/capture/capture-clips.ps1 -Clip hover|tour|theme|mascot`: direct ffmpeg (`gdigrab`) fallback recorder for quick standalone GIF captures in `docs/media` (switches theme/mascot in quick settings and restores them afterwards).

Before capturing: turn on the tabs the scripts visit (Media, Stats, Weather, Pomodoro, Prayer, Today, AI usage, FX Rates; they are found by tooltip, so other tabs may stay on; prayer times are off by default on new installs), and play a track whose cover art and lyrics you may publish (your own or royalty-free), so no commercial album art or lyrics end up in the README.

`tools/capture/capture-lib.ps1` holds the shared helpers (dock lookup, auto-crop, mouse movement, redaction, and `Set-Theme` / `Set-Mascot` / `Get-Look` / `Restore-Look`, which click the quick-settings radios by their AutomationId because the labels "Matcha" and "Hojicha" appear in both the Theme and the Mascot row). Review every image for private data before committing, and put your settings back (theme, Pomodoro tab, Stats module) when done.

Not captured: the Gaming readout, notification capsules, and the WhatsApp, Email and Discord cards (they show real conversations).

## Promo video (Shorts / Reels)

`promo/` uses [Remotion](https://www.remotion.dev) to edit recorded clips into a 1080 x 1920, 30 fps vertical video (`MochiDockShort`). With the Media opening and Stats tour, the edit runs 32 s with the gaming scene and 29.5 s without it. Remotion is an npm dependency under its own licence and is separate from the app. Rendering runs on the CPU. Recorded clips, renders, music and `node_modules` are git-ignored.

1. Prerequisites: ffmpeg (`winget install Gyan.FFmpeg`) and Node.js (`winget install OpenJS.NodeJS.LTS`).
2. Start MochiDock yourself, turn off "Exclude from screen capture", switch on the Media, Stats, Weather, Prayer and FX Rates tabs, and play a track you may publish (Pixabay Music or the YouTube Audio Library; most are instrumental, so the Media card shows no lyrics).
3. From the repository root, in an **elevated** PowerShell, start `pwsh -NoProfile -STA -File tools/capture/backdrop.ps1`; in a second elevated window run `pwsh -NoProfile -STA -File tools/capture/capture-promo.ps1` and leave the mouse alone for about two minutes. It writes `promo/clips/promo-*.mp4` (hover, media, stats, weather, prayer, fx, theme, mascot), blurs the integration status line in the quick-settings clips, and puts the theme and mascot back. Options: `-Only promo-media,promo-hover` re-records single clips; `-Width` / `-Height` (default 660 x 420 physical pixels; use 880 x 580 when the dock is at 125 % size) widen the area on a high-DPI screen, for example `-Width 990 -Height 630` at 150 % scaling (the Remotion crop rectangles in `promo/src/MochiDockShort.tsx` are in clip pixels and must match the clip size).
4. Review every clip for private data. If a clip shows cover art or lyrics you may not publish, make a `<name>-blur.mp4` beside it (ffmpeg `crop` + `boxblur` + `overlay` over the cover, title and lyric areas, as was done for the first cut); `prepare-clips.ps1` prefers it.
5. In `promo/`: `npm install`, then `npm run clips` (copies the clips into `public/clips`), `npm run studio` to preview, `npm run render` for `out/mochidock-short.mp4` and `npm run cover` for a cover frame.

Choose `MochiDockV2` in the same Studio to preview the dark showcase. With all the footage present, it runs for 45 seconds, including the 3.5-second end card. Gaming and the power scene each add five seconds when their recordings are available.

For the opening and CPU shots, pause media playback and run `tools/capture/capture-promo.ps1 -Only promo-idle-media,promo-cpu-ready -Width 880 -Height 580` from an elevated PowerShell with the backdrop and the dock at 125 % size. This records the resting capsule opening into Media, then a CPU shot after the charts and process list have had time to load. The previous idle-to-Stats take remains available through `-Only promo-idle-hover`.

For a live Stats tour, run the same command with `-Only promo-stats-tour`. It records CPU, GPU, Memory, Drives and Power & Batteries in one take and saves `promo/clips/promo-stats-tour.mp4`. Run `npm run clips` to pick up both optional clips. Review process, drive and device names before publishing.

Gaming mode: the dock stays at the top of the screen and needs a running game in borderless windowed mode (or fullscreen with fullscreen optimizations, not exclusive fullscreen). Record it separately, **without** the backdrop, from an elevated shell: `pwsh -NoProfile -STA -File tools/capture/capture-promo.ps1 -Gaming` (or `-Only promo-gaming`). It counts down (`-GamingCountdown`, default 20 s) so you can switch to the game, then records `-GamingSeconds` (default 12) of the top of the screen, centred on the dock, without moving the mouse. The "Gaming mode" scene is skipped when `promo-gaming.mp4` does not exist (`npm run clips` writes `public/clips/manifest.json` with the clips that exist). The dock is about 850 px wide at 125 % size, so record the other clips with `-Width 880 -Height 580`; the crop rectangles in `promo/src/MochiDockShort.tsx` assume that clip size and the dock at x 28 to 801.
